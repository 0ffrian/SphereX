# Decisions: Gemini artistic layer

> **Part of:** the decision log ([index](README.md)) · **Holds:** the Gemini layer: scope, offline behaviour and its contract · **Authority:** highest; an entry here wins over [rendering/](../rendering/README.md) and [architecture/](../architecture/README.md) (see the index for precedence)

## D-07 Gemini artistic layer

- **Decision:** Use the rendering doc's method (§6.6). Gemini repaints albedo using a hillshade of the baked height map as its reference. Output whose edge correlation is below 0.3 is rejected. The call is made server-side only and the result is labelled "AI-made".
- The architecture spec's seamless-tile-plus-triplanar method (§6.2) applies only to the browser-shader kinds (D-01).

| Q-122 | Gemini layer contract (issue #14, PR #48; R6.6, A6.2, D-07, D-24, D-25, D-32, R10 "behind the admin token"). Was Q-87 in the PR; renumbered because main uses Q-87 for the sky endpoints and open PRs claim Q-114 to Q-121 and Q-130 to Q-145. Nothing in D-16, R3.4 or R10 names the admin mechanism, the endpoints or where the AI albedo lives. Implemented as ASSUMPTIONS: (1) **Admin token** `SX_ADMIN_TOKEN`, sent as `X-SX-Admin-Token`, compared in constant time; unset or blank → admin endpoints answer 404, a missing or wrong token → 403. The POST is meant for `curl`: CORS allows `GET` only, so no browser page can call it (intended). (2) **Endpoints.** `POST /v1/admin/objects/{id}/gemini-repaint[?refresh=true]` always answers 200 with `{id, status: applied\|code, reason, detail, missing, edge_correlation, edge_correlation_min, model, cached_at, from_cache, checks, provenance, label?, size?, layer?, albedo_url?}` (`cached_at` is null when unknown); `GET /v1/objects/{id}/albedo-ai` returns the same body for the last applied repaint, checked against the bake the viewer shows, without a card build, a bake or a Gemini call; `GET /v1/objects/{id}/albedo-ai.webp` serves the checked bytes (header `X-SX-Layer-Tag: artistic`, exposed through CORS) or 404 `albedo_ai_unavailable`. (3) **First-stage refusal.** If the pipeline answers with a first-stage card (`measuring` not empty, issue #41), the POST returns `code` with reason `measuring` and calls nothing: the finished job rebakes with the final params and would orphan a paid repaint. If the card cannot be built (`CacheMissOffline`, `UpstreamUnavailable`) the reason is `card_unavailable`, still a 200. (4) **Files outside the static root.** The AI files are `albedo_ai.webp` plus `gemini.json` (stamp, tag `artistic`, label "AI-made", model, prompt, correlation, hashes) under `SX_TEXTURES_AI_DIR` (default `<SX_CACHE_DIR>/textures-ai`), at the same relative path as the code maps' R6.7 size directory; per-object pointers are `<SX_TEXTURES_AI_DIR>/pointers/<sha256(id)>.json`. `SX_TEXTURES_DIR` is mounted at `/data/textures` (R6.7), which has no status check and stays on under `SX_OFFLINE=1`, so the painter refuses to start when the AI root is inside it. A rebake no longer removes the AI files; item 5 makes them stale instead. (5) **Pointer stamp.** The pointer and `gemini.json` store `paint_version`, `bake_id`, `generator_version`, the baker `rules` (`BAKER_RULES_VERSION`), `seed`, `size` and the code `bake_key`. The status compares them with the bake the viewer shows: a saved or pre-baked asset's RenderParams (disk only), else `GENERATOR_VERSION` and `seed_for(id)`; then with the code `bake.json` key and the image hash. Any difference answers `stale` (code colour), so a version bump or a new seed never shows an AI albedo checked against another relief (D-07). (6) **`layer` is a D-32 `Layer`** (`id`, `tag: artistic`, `tier: 5`, `description`, `requires`; validated against `render-params.schema.json#/definitions/Layer` in the tests); "AI-made" moved to a top-level `label`. (7) **`edge_correlation` is a process check, not a value about the object**, so it has no provenance tag; this is the one deliberate exception to the "provenance on everything" rule (CLAUDE.md), recorded here rather than only in the code: it is reported under `checks.edge_correlation` (`kind: process_check`, `formula`, `min`), not in `provenance`. (8) **POST vs. GET after a failed refresh.** The POST reports this attempt (`code` and its reason); an earlier verified repaint for the same bake is left in place, so GET keeps answering `applied`. Intended: a failed retry must not take down a good, checked layer. (9) **Viewer.** RenderParams `textures` has no slot for it and R3.4 / `shared/schemas/` were not changed, so the viewer must read the status endpoint; the viewer swap-in and the "AI-made" badge are a frontend follow-up, not built in #14; adding an optional `textures.albedo_ai` (and an `albedo_ai` layer) to R3.4 is the alternative. Only the desktop size (2048×1024) is painted; the mobile 1024×512 bake keeps the code colour. (10) **Cache.** The D-25 cache stores the decoded image bytes (source `gemini`), not the JSON reply, and only after the image passes the decode and D-07 checks, so a rejected image is never replayed; a `refresh` whose live call fails reports that failure instead of serving the older entry (both differ from the plain D-25 order). With no key set, a cached repaint is still used (keyed by `SX_GEMINI_MODEL`). (11) **Cost and concurrency.** At most one repaint per object at a time (a per-object lock covers the call and the image, meta and pointer writes; other objects run in parallel). After a live call for an object, another live call for it is refused for `SX_GEMINI_COOLDOWN_S` (default 60 s, reason `cooldown`); cache hits are never refused. Only failures where the request was turned away before any work are retried: connection failures (`ConnectError`, `ConnectTimeout`, `PoolTimeout`) and HTTP 429 and 503. HTTP 500, 502 and 504 and read errors may come after Google generated (and billed) the image, so they are not retried and one admin call is billed at most once. The per-object locks are a fixed stripe of 64 and the cooldown map drops entries older than the cooldown, so neither grows with the number of ids. The JSON status memoises the image hash by file mtime and size; only the `.webp` route reads and hashes the bytes it sends. A failed live call is logged as a warning naming the model, and an unexpected client error with its traceback. The offline and refresh refusals run before the bake. The reply is streamed, with `SX_GEMINI_TIMEOUT_S` as a whole-call deadline and a 32 MiB size cap checked between chunks. (12) Q-29 is implemented as a switch, `SX_GEMINI_OFFLINE_CACHE` (default 0 = D-24: off offline); with it on, `refresh=true` answers `offline` ("a refresh needs the network"). Confirm or replace. **Spec:** [A6.2](../architecture/generators.md#a62-optional-gemini-artistic-layer) owns the contract (routes, gate, files, cache, reasons); open here: the admin mechanism, the `albedo_ai` slot (item 9) and the Q-29 default. | Atish, Kevin | Open (implemented as proposed) |
