| Q-178 | **OUTLIER in the area pipeline (extends Q-139 to Discovery; A17.2, A16.5).** Discovery cannot know which dots are a mover's core, and masking `OUTLIER` as Stage 2 does removes Eros from 15 of its 16 frames, so it can never be found blind. Proposal: in `core/area/dots.py`, `OUTLIER` is never masked; a dot whose aperture holds `OUTLIER` pixels keeps them and lists `OUTLIER` in its `flags`; the glitch rule (a dot must repeat in 3 frames of its visit, both detectors counting) removes one-off hits; hardware flags (the rest of Stage 2's reject list) still mask. Discovery dots on the sky are not drawn hollow for it; the flag is shown in the Result card's dot list and in the export's `flags` column, which meets Q-139's condition for the area pipeline. Track's spectrum keeps Q-139 as written (hollow point and "flagged OUTLIER"). Spec: [A17.2](../architecture/moving-objects/area-backend.md#a172-dots-dotspy), [A16.5](../architecture/moving-objects/area-search.md#a165-honesty-rules). Listed for Moon's review in Q-202 item 1. | Moon, Kevin | Proposed |
| Q-179 | **Parallax-aware pair test in Discovery (amends Q-146 item 3 "paired across visits by rate and direction"; A17.4).** The direction measured inside a 6.4 min visit carries SPHEREx's orbital parallax (Q-134): on Eros it differs by 25° from the direction between visits, so the fixed tolerance of A17.4 (20°, rate ratio 1.5) rejects Eros's own pair. Proposal: the between-visit velocity `v_AB` is close to the geocentric rate (parallax adds at most `2·A_par` over a day), while the inside-visit velocity is `v_in = v_AB − w·u`, with `w` SPHEREx's velocity relative to the geocentre projected on the sky (one Horizons vector per visit, `COMMAND='-163182'`, `CENTER='500@399'` [verify]) and `u = 1/Δ ≥ 0` fitted. A pair passes when the residual perpendicular to `w` is at most `v_tol = max(0.1 deg/day, 3σ_v)` [verify] and `u ≤ 1/0.05 AU`; tracks need mutual best candidates and a best residual at most 0.5 times the next. Fallback if `w` is not available on Day 0: rate window only, then the same ranking. D1 must show one `track` on the Eros area. Spec: [A17.4](../architecture/moving-objects/area-backend.md#a174-join-across-visits-joinpy). Listed for Moon's review in Q-202 item 2. | Kevin | Proposed |
| Q-180 | **Known-object check uses SkyBoT for candidates and Horizons from SPHEREx for positions; new verdict `unchecked` (A17.5, A16.5; applies Q-138 to Area search).** SkyBoT answers for an IAU observatory code and SPHEREx has none (Q-145); the adapter asks the geocentre (`backend/app/adapters/skybot.py:84`, `-loc 500`), up to about 4 px off for Eros. Proposal: one SkyBoT cone per visit, padded by `p_max` (60″ [verify]) and the motion over the visit, lists candidates (V ≤ 22 [verify]); each candidate gets one Horizons TLIST from `500@-163182` at every frame time of the area, through the cache and the Horizons one-request gate; matches and the `/known` positions use those (`model_dependent`). A track whose check failed (SkyBoT or Horizons) is `unchecked`, never `unexplained` (`skybot:<visit>`, `horizons:<designation>` in `missing`); "unexplained" is dated ("as of" the SkyBoT `fetched_at`). `SkybotBody` gains the position error and motion rates. Spec: [A17.5](../architecture/moving-objects/area-backend.md#a175-known-object-check-matchpy), [A16.5](../architecture/moving-objects/area-search.md#a165-honesty-rules), [A3.5](../architecture/data-sources.md#a35-imcce-skybot); risk in [A14](../architecture/risks.md#a14-risks-and-open-questions). Listed for Moon's review in Q-202 item 5. | Kevin, Atish | Proposed |
| Q-181 | **Track is a split-pane kind with no rail tool; its entry points and width (amends Q-131 "tool id"; A19.2, A20.1; uses Q-171).** Track has no `ToolId` and no rail button. It opens with `openPane({ kind: 'track', objectId, from })` from: Area search's Known card (**Track it**), a found-blind Result card (**Open in Track**), the object panel of any `moving = true` object (a new **Track it** button), and a `track=<id>` link. It receives only the resolved object id. Its split width is 50 %, as Build (the mock-up's 62 % is not used). An id with `moving = false` is refused in the frontend (`track:not_moving`). Spec: [A19.2](../architecture/moving-objects/track.md#a192-entry-points), [A20.1](../architecture/moving-objects/track-ui.md#a201-where-track-lives), [A21.8](../architecture/sky-shell-behaviour.md#a218-split-pane) (pane kinds: Q-171). | Atish, Moon | Proposed |

| Q-185 | **Marker between exposures (clarifies Q-138 and Q-142; A19.4, A20.3).** Q-138 forbids interpolating from an hourly table; Q-142 makes the marker follow the slider "inside the SPHEREx windows", which needs positions between exposures. Proposal: between exposures the marker is linear in the unit vector between the 10-min SPHEREx-centred samples of the path ephemeris, with the error bound stated (about `A·(π·h/P)²/2`, 1.4″ for Eros [verify]); at an exposure time it snaps to the exact TLIST position; the slider range is the Track window (the object's `moving_windows`). | Q-186 | **A measurable test for "the coma fills the aperture" (amends Q-144; A19.8).** The 3′ coma always covers the 3 px aperture and the 6 to 9 px annulus, so Q-144's rule as written always refuses. Proposal: concentration `C = F(r ≤ 1.5 px)/F(r ≤ 3 px)` with the Stage 2 weights; a steady 1/ρ coma gives 0.5; a frame with `C ≤ 0.5 + δ` (δ = 0.05 [verify]) is refused as `extended_source:<frame_id>` (and `spectrum:extended_source` when all are); otherwise shown with the caption "aperture, not total flux; background taken from inside the coma". Stretch only (Q-137). Spec: [A19.8](../architecture/moving-objects/track.md#a198-extended-sources), which adds `C_psf`, the median `C` of isolated, unmasked catalogue stars in the same frame ([A19.6](../architecture/moving-objects/track.md#a196-star-list-for-movers)): a frame with `0.5 + δ < C < C_psf − δ` is shown with the caption. | Moon | Proposed |
| Q-202 | **Review of the Area search fixes (9 Nov 2026).** Q-146 is Moon's agreed plan (accepted by Atish). The 9 Nov 2026 spec pass fixed the audit's blockers in A16 to A18 and, doing so, changed parts of that plan. Each change is written in the spec (most as **Proposed**); Moon accepts, amends or rejects each item. (1) Discovery no longer masks `OUTLIER`; flagged dots are not drawn hollow on the sky (Q-178; [A17.2](../architecture/moving-objects/area-backend.md#a172-dots-dotspy), [A16.5](../architecture/moving-objects/area-search.md#a165-honesty-rules)). (2) The pair test is parallax-aware, not a fixed 20° direction and 1.5 rate tolerance; pairs need mutual best candidates (Q-179; [A17.4](../architecture/moving-objects/area-backend.md#a174-join-across-visits-joinpy)). (3) Thresholds re-derived: `rate_min = r_match / Δt_v` per area (0.0034 deg/day on Eros); `rate_max = min(1.2 deg/day, area size rule)`; the glitch radius grows with time; `k_visit = min(3, frames in the visit)` counting both detectors; the star label is set per tracklet with a magnitude-dependent radius; new possible reasons `no_partner` and the counted-only `static_one_visit` ([A17.3](../architecture/moving-objects/area-backend.md#a173-glitches-stars-and-fixed-dots-cleanpy), [A17.4](../architecture/moving-objects/area-backend.md#a174-join-across-visits-joinpy)). (4) Step order: glitch, then fixed and star (star now judged per tracklet), then join; Q-146's five steps are kept, step 3 renamed "Drop stars and fixed dots" ([A17.3](../architecture/moving-objects/area-backend.md#a173-glitches-stars-and-fixed-dots-cleanpy), [A18.6](../architecture/moving-objects/area-ui.md#a186-discovery-card)). (5) The known-object check takes positions from Horizons seen from SPHEREx; new verdict `unchecked`; "unexplained" is dated (Q-180; [A17.5](../architecture/moving-objects/area-backend.md#a175-known-object-check-matchpy), [A16.5](../architecture/moving-objects/area-search.md#a165-honesty-rules)). (6) The found-blind sentence no longer says "found without being told where to look"; it says the area was chosen because Eros crossed it. Q-146 item 4's "Demo moment: Discovery finds Eros blind" stays, worded honestly ([A16.1](../architecture/moving-objects/area-search.md#a161-why-and-who), [A16.5](../architecture/moving-objects/area-search.md#a165-honesty-rules), [A18.7](../architecture/moving-objects/area-ui.md#a187-result-card)). (7) The frame search for an area is a grid of small fixed-position cones with an `s_region` overlap test, a backend time filter and coverage masks, not PR #53's path search ([A17.1](../architecture/moving-objects/area-backend.md#a171-area-and-frames-framespy)). (8) Results are `derived.area` entries in the D-25 cache, not a separate file tree; `params_hash` covers the inputs' SHA-256 ([A17.10](../architecture/moving-objects/area-contract.md#a1710-cache-offline-and-determinism)). (9) Area cards are feature cards in the object card's slot at 340 px (not 408 px in the island), minimised to the island's `progress` pill (Q-172; [A18.4](../architecture/moving-objects/area-ui.md#a184-cards-and-minimise), [A21.5](../architecture/sky-shell-surfaces.md#a215-overlay-surfaces-island-object-panel-object-card)); visits are chosen in the Discovery card, not the transport (Q-175; [A18.3](../architecture/moving-objects/area-ui.md#a183-visits-and-blink), [A21.9](../architecture/sky-shell-behaviour.md#a219-transport-session-search-pill)); the blink starts only when pressed and has a stop ([A18.3](../architecture/moving-objects/area-ui.md#a183-visits-and-blink)). (10) The "Track card" is renamed "Result card"; its hash key is `atrack=` (Q-182, Q-173; [A18.7](../architecture/moving-objects/area-ui.md#a187-result-card), [A18.9](../architecture/moving-objects/area-ui.md#a189-state-api-client-accessibility-performance)). (11) Owners: the star list for movers is Kevin's only (not "Kevin, Moon"); Track backend Kevin, Track screen Atish (Q-183; [A16.3](../architecture/moving-objects/area-search.md#a163-architecture)). (12) Schemas: new `area-index.schema.json`; `/dots` gains `frame_id`, `detector`, `x`, `y`, `flags`, `bandwidth_um`; the summary gains `coverage`, frame `detector` and `s_region`, and more step counts; the fixture area has 4 movers (adds one `unchecked`) ([A17.8](../architecture/moving-objects/area-contract.md#a178-endpoints), [A17.9](../architecture/moving-objects/area-contract.md#a179-schemas-and-fixtures)).
