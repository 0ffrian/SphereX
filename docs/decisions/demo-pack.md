| Q-206 | **The pre-built pack never hides a measured spectrum (issue #75; amends Q-164 (1) and (3); A4.4, A5.4, D-25).** **Facts (10 Nov 2026 gap analysis, main @ ba23552):** `AssetStore.lookup` returned the pack before a generated asset, and the object job answered from it without measuring. On a real D-25 cache WISE 0855's card said "no SPHEREx spectrum" and lost `emissive`, `flux_pulse` and `spherex_ir` while `/spectrum` gave 237 points; Epsilon Indi B lost `emissive` and `flux_pulse` with 297 points; Barnard's Star, RW Aur and R Dra were affected too. The tests switch the pack off (`make_settings`), so nothing caught it. **Rule:** (1) `AssetStore.lookup` reads the **generated** asset (D-25 `derived.asset`) first, then the pack. A generated asset is saved only from final inputs, so it holds the measured spectrum. (2) A pack asset whose RenderParams list `spectrum` in `missing` (all 16 rows today, Q-164 (3)) is a **stand-in**, not a saved answer: `/card` and `/render-params` run the object's job, which builds live (stages 1 to 7 from the cache or the network) and answers with the live build when it has a measured spectrum and the same `type` as the pack. (3) The pack answers (status `saved`, the `PREBUILT_NOTE` stays true) when the live build has no spectrum (a `frames = false` row, or no frames cached), when its type differs (offline with the frames cached but not the catalogue answer, the live build is a `candidate` sketch; the pack's catalogue card is kept), or when it raises any exception (never blank). Nothing is mixed: a reply is either the whole live build or the whole pack. (4) The live build of a stand-in is **quiet**: it publishes no first-stage or partial answer, and bakes and saves nothing until it has won; a build that loses (even with final inputs) is never saved, so it cannot replace the pack on the next request. Online, `run` answers with the live build if it is final within `SX_FIRST_ANSWER_WAIT_S`, else with the pack (no card that flips back); offline it waits for the final, as for any object. (5) Each layer is checked against the contract on its own: a generated asset saved under an older schema falls through to the pack. (6) A pack asset that lists no `spectrum` code is still served directly, as before. (7) `pipeline.saved()` (the Gemini endpoints) returns what `run` answers: for a stand-in whose job has finished, that job's answer. **Tests:** `backend/tests/test_pack_shadowing.py` runs with the committed pack on: the five star rows with frames in the fixture cache answer `generated`, byte-equal to the pack-less build; a lost catalogue and a build with no spectrum answer the pack; a final live build is saved and then wins over the pack; a losing build with final inputs is not saved; an invalid generated asset falls through to the pack; any live failure answers the pack; online, the pack answers while the quiet build runs and nothing intermediate is published. The fixture lists are cut at MAXREC=3, so the layers that need more points stay refused in the tests; on the event cache they are drawn. **Cost:** an object with a pack asset now runs its job on first request (as an object without one does); jobs are reused for `SX_JOB_TTL_S`. | Kevin | Proposed (needs a second team member) |
| Q-204 | **Determinism of PNG maps across machines: chunks and image data, not deflate bytes (issue #79; amends Q-164 (4); R0 principle 5, A1 item 4, R6.7, A12).** **Facts (10 Nov 2026):** with the same locked Pillow 13.0.0 (its PNG encoder uses zlib-ng 1.3.1), 'Oumuamua's `height.png` and `normal.png` rebuilt on a Windows desktop differ in bytes from the committed files (by 5 bytes each). The other 4 pack PNGs match byte for byte. **Rule:** (1) **Same machine:** the same card and seed give byte-identical textures. Two rebakes on one machine agree, and the baker's same-machine SHA-256 test stays byte-exact.
