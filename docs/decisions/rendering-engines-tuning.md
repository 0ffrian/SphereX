## D-38 Issue #93: engine speed, seeded patterns, physics corrections and new card fields (Decided by Atish, 11 Nov 2026)

- **Context:** after PR #89 the D-37 engines froze the page on the first open (the fly shader took about 56 s to compile on a cold ANGLE D3D11 cache), the world engine ran below 30 fps, card objects showed shifted copies of one pattern, several physics rules used the wrong law or constant, and the card lacked values the engines need (eccentricity, host luminosity, star mass and luminosity, star rotation periods).
- **Decision:** Atish (team lead, with full authority over the card contract and the engines) decided on 11 Nov 2026 to implement issue #93 on branch `fix/93-engines`, in four phases: (1) first-open freeze and frame rate, Q-337 to Q-346; (2) repeating patterns, Q-347 to Q-354; (3) physics, Q-355 to Q-362 in [physics-fixes.md](physics-fixes.md) (item 3.7 not merged, Q-361); (4) datasets and the card contract, Q-363 in [contract.md](contract.md) and Q-364 to Q-366 in [catalogue-values.md](catalogue-values.md). The engine look changes are decided; those Moon (the engine author) should see are marked "Moon to confirm".
- **Why:** the demo draws these engines at + Artistic on the A15 (Q-132, Q-287); a frozen page or two planets with the same clouds is the first thing a visitor sees, and a physics constant must come from a cited source (data first).
- **Amends:** D-37 (the determinism bullet: a card star now takes a seed for its surface and spots, Q-349; the frame-rate bullet: compile times measured, the A15 run still open), Q-306, Q-316, Q-304 and Q-334 through the entries below.
- **Status:** Decided (Atish, 11 Nov 2026); built on `fix/93-engines`, except Q-361 (open) and Q-346 (deferred).

## Q-337 to Q-346 Phase 1: first-open freeze, frame rate, controls (issue #93)

Status for all: **Decided (Atish, 11 Nov 2026)**, except where an entry says otherwise. Engine changes inside copied code are `@deviation (#93 1.x)` blocks (Q-354). Spec: [R5.9](../rendering/engines.md#r59-prototype-engines-d-37).

- **Q-337 Loop bounds `N+uZ0` so the shaders compile fast (#93 1.1, 1.9).** On ANGLE D3D11 (Chrome's default on Windows) fxc unrolls every loop with a constant bound. Each constant bound N in `WORLD_FS`, `FLY_FS` (with NOISE's fbm and ridge) and the star shader becomes `N+uZ0`, with `uZ0` a uniform never set (always 0): the loops run as before but stay loops. Pixels are unchanged within rounding. Measured cold (RTX 4060 Ti desktop, `frontend/scripts/engine-bench`; **corrected 12 Nov 2026** by the #93 blue team): `FLY_FS` 22 to 43 s under load (not "about 20 s"; the earlier 56 s and 78 s baselines were measured under uncontrolled load), the globe programs 2.3 to 4.6 s, the star shader 1.2 to 1.7 s, the rock shader 1.9 to 2.1 s (still synchronous). The A15 is not measured yet (R12 #55). A warm shader cache gives milliseconds only within one Chrome session, or across launches with `--enable-features=ANGLEPerContextBlobCache` (Q-368). `ADV_FS` and `GAS_FS` keep their source. **Amended by:** [Q-384](rendering-engines-perf.md#q-381-to-q-387-performance-waves-issue-93) (the fly shader has 14 loops, all `N+uZ0`; `FLY_FS` cold about 22 s median). Owner: Atish.
- **Q-338 Background compile and `whenReady()` (#93 1.2).** The world engine submits its programs without reading a status (`compileStart`), polls `KHR_parallel_shader_compile` (`compileDone`) and reads the result once linked (`compileEnd`, which throws the compile or link log as `compile()` did). `WorldEngine.whenReady()` resolves when every program is linked (it checks every 16 ms, so the page keeps running) and rejects with the log; the stage then takes the three.js path, as a failed start always did. Without the extension the next step blocks as before. Every program is linked before the first step or draw (`WorldGL.link`). **Open:** the star engine still compiles synchronously (its slices run through `new Function`); the rock engine too (1.9 to 2.1 s cold; R12 #56). **Amended by:** [Q-381](rendering-engines-perf.md#q-381-to-q-387-performance-waves-issue-93) and [Q-382](rendering-engines-perf.md#q-381-to-q-387-performance-waves-issue-93) (both now compile in the background, with their own watchdogs). **Never stuck on "Forming" (#93 regression fix, 12 Nov 2026).** `app/engineWatchdog.ts`: the stage takes the three.js path if the shaders are not ready after 60 s (globe) or 180 s (fly) (`readyOrTimeout`), if the world has not formed after 90 s counted while on screen (`FormClock`), on an exception while starting or stepping, or on a lost context; these limits are UI pacing, not physics. `dispose()` never blocks: it releases the context only once the driver reports every program done (polled every 100 ms) and, if a compile is still pending after 180 s, leaves the context to the browser without calling `loseContext()`. The stage creates its engine one tick later, so React's development double mount builds one engine. The "Forming" overlay shows the build loader (static under reduced motion), "Preparing the graphics. The first time can take a minute." while compiling, then a progress bar of the spin-up. Owner: Atish.
- **Q-339 Engine roles and skipped draws (#93 1.3, 1.6).** `new WorldEngine(canvas, { role })` with `role` `'globe'`, `'fly'` or `'both'` (the prototype's split page, used by parity). A globe engine never compiles `FLY_FS` (it submits it the first time it flies); the fly engine does not ray-march the globe hidden beside its view (its canvas is 1.67 times its pane wide; `W.view` is still set for `flyAimPeak`, `flyAimDefault` and `globePick`). No world is drawn under the opaque "Forming" overlay; "Forming" also covers the shader compile, before there is an engine. A globe-role engine ignores `setFly(true)` (it would link `FLY_FS` synchronously). **Amended by:** [Q-384](rendering-engines-perf.md#q-381-to-q-387-performance-waves-issue-93) (the fly engine never compiles `WORLD_FS`: 3 programs). **Build steps wait for the engine (#93 regression fix, 12 Nov 2026).** While a world engine draws the body and has not reported `onFormed` for this card and preset, `useMould` gets `hold` and stays in the phase `'forming'`, with the first step shown in progress; once the engine is ready and the spin-up is done the steps play from the start. A failed engine unmounts (three.js path), which ends the hold; reduced motion still shows the body built at once; Replay of a formed world plays at once. Owner: Atish.
- **Q-340 Pixel footprint at full resolution (#93 1.4).** The fly view's pixel footprint (which fades noise octaves finer than a pixel) used the drawing-buffer height, which the resolution scaler changes on slow frames, so the ground texture changed while flying. It now uses the full-resolution height (`uR.y / uScale`; `core.js` passes the scaler's factor as `uScale`), so a scale change alters sharpness only. **Amended by:** [Q-384](rendering-engines-perf.md#q-381-to-q-387-performance-waves-issue-93) (B9: the footprint follows the eased real pixel, `uScale = scale / W.fp93`). Owner: Atish.
- **Q-341 One terrain build per input set (#93 1.5).** `engine/worlds/terrainCache.js` (hand-written, not extracted) builds the terrain and its river routing once per set of inputs for every engine on the page (key: seed, `seed3`, ocean fraction, gravity and the terrain options; the last 4 kept) and shares it read-only. The second engine of a world takes 45 ms instead of 530 ms. Owner: Atish.
- **Q-342 Resolution scaler at 30 fps and pixel-ratio caps (#93 1.7; amends Q-306, Q-316 (4)).** The world engine's scaler aims at 30 fps: it shrinks above 34 ms (was 42) and grows below 22 ms (was 19); a gap over 250 ms (a pause between redraws of a still world) is not counted. The device pixel ratio is capped at 1.0 for the fly engine, 1.25 for the globe engine and 1.5 for `'both'` (was 1.5 for all). `window.__sxPin` still pins the scale for parity. The star and rock engines keep their own 1.5 cap. The A15 frame-rate check is still open (R12 #43). **Amended by:** [Q-384](rendering-engines-perf.md#q-381-to-q-387-performance-waves-issue-93) (steps ×0.8 at most once a second and ×1.25 at most once every 3 s, range 0.45 to 1, at 34 and 20 ms). Owner: Atish.
- **Q-343 Gas solver at most 3 steps a frame (#93 1.8).** `GasSim.step` costs about 4.5 ms; the engine now runs at most 3 steps a frame (was 8) and drops a backlog of a whole step or more, so a slow frame never schedules more work. A giant that needs more than 3 steps a frame runs slower than one day per second, and the caption then states the real rate at 60 fps instead of "One second here is one Earth day" (HD 189733 b about 15 h per second; it needs about 4.7 steps a frame). **Amended by:** Q-380 (the rate is taken at the measured frame rate, not 60 fps). Owner: Atish.
- **Q-344 Globe and close-up controls (amends Q-316 (2)).** On the world globe a press that moves less than 4 px is a click and picks the place the close-up goes to (with the close-up open); a longer press drags and turns the globe, and the arrow keys turn it, also with the close-up open (the pick used to fire on every press, so the globe could not be turned). The close-up's drag follows the hand (it turned against it). The globe's alt text says "Drag or use the arrow keys to turn it". **Direction (#93 regression fix, 12 Nov 2026):** the globe's drag follows the hand on both axes (it moved against it), and the arrow keys and the Details rotate arrows move the surface the way the arrow points (`globeTurn`, `globeTurnBy` in `worldStore.ts`); the light turns with the view, so the terminator stays put. Click-to-pick and the close-up drag are unchanged. Owner: Atish.
- **Q-345 Engine bench scripts.** `frontend/scripts/engine-bench/` (Playwright pages and `bench-cpu.js`, research tools, not in CI) measure cold compile per program, the background compile, fly-view frame time and picture stability, pattern correlation, preset pixel checks and CPU costs. The numbers in Q-337 to Q-353 come from an RTX 4060 Ti desktop; the same pages are to be run on the A15 (R12 #43). Owner: Atish.
- **Q-346 Phase 1b: the fly engine adopts the globe's climate state.** The fly engine would take the globe engine's spun-up clouds and climate instead of running its own simulation (Q-313). **Status:** Deferred (Atish, 11 Nov 2026). **Amended by:** [Q-385](rendering-engines-perf.md#q-381-to-q-387-performance-waves-issue-93) (built on `fix/93-wave2-sim`, merging: one simulation per world, in a Web Worker). Owner: Atish.

## Q-347 to Q-354 Phase 2: repeating patterns (issue #93)

Status for all: **Decided (Atish, 11 Nov 2026)**; the look changes are marked "Moon to confirm". The prototype's own presets keep their scalar seeds, so `?parity=1` and `?preset=` draw as before: the world presets on the globe, the star rows and the rock bodies measured pixel-identical (`engine-bench/patterns.html?what=presets`). The fly-view changes of Q-351 and Q-352 apply to every world, presets included. Spec: [R5.9](../rendering/engines.md#r59-prototype-engines-d-37), [R7.7.1](../rendering/renderers/world-engine.md#r771-world-engine-values).

- **Q-347 Seeds: a 32-bit hash and `seedVec` (#93 2.1, 2.9; amends Q-304).** `frontend/src/engine/seed.ts`: `hashString32` (FNV-1a, then the murmur3 `fmix32` finaliser), `hashInt32`, and `seedVec(hash)`, three integers in [0, 256) that the shaders add to their noise coordinates as a vec3. A card world's seed is the full 32-bit hash of the card id (was FNV-1a folded to 1..997, so two of 20 worlds shared a seed about 17 % of the time); the shaders take `seed3 = seedVec(seed)`. Seeds are `artistic`. Measured: two colliding Earth-like cards, detail correlation 1.000 to 0.196; card stars, identical to a median of 0.023; fly-path stability (`flypath.html`, ground tiles matched frame to frame) TRAPPIST-1 f 0.53 to 0.68 and the prototype's Earth preset 0.34 to 0.70; fly frame time +8.8 % (TRAPPIST-1 f) and +2.7 % (Earth). Owner: Atish.
- **Q-348 Card gas giants: tracer noise from the sphere direction (#93 2.2).** `GAS_FS` read one unseeded 512 × 256 texture tiled 4 × 3, the same on every giant, and the jets never smeared the copies out. A card giant (`uNzSph = 1`) now reads `fbm(dir · (24, 54, 24) + uSeed3, 4)`; presets keep the texture. The three.js fallback `GasWorld.ts` fills its noise texture from sphere directions the same way, so the fallback's look changes for every object, presets included. Moon to confirm the look. Owner: Atish.
- **Q-349 Card stars seeded (#93 2.3; amends D-37's determinism bullet).** A card star passes `so` (seedVec of the card id's hash) as `uSO`, added to granulation, supergranulation and the close-up filters, and its hash to the spot RNG as `rng(1729 ^ seed)`. The first three spot groups keep their fixed longitudes (they face the viewer); their latitudes, sizes and the rest move. The prototype's presets and the Sun keep `uSO = 0` and `rng(1729)`. Flares and plasma keep the prototype's fixed seeds. Moon to confirm the look. Owner: Atish.
- **Q-350 Layers that had no seed (#93 2.4, river relief).** Sea-ice tint, convective clouds, waves, fly-view sea ice and slope rock colour add `uSeedN` (0 for presets); the river relief noise is offset by the card's `seed3` (`t.so`, set by `terrainCache.js`, whose key holds `seed3`). Saturn's ring texture is not seeded: no card world draws rings. Not changed: the CPU terrain hash and the octave lacunarity (a backend change and re-bake, after the event). Owner: Atish.
- **Q-351 Planet-fixed detail and octave fade (#93 2.5, 2.6).** The fly view's gullies and the gas giant's small-scale detail were laid on the plane under the camera, so they slid as the camera moved. They now sit on the faces of a planet-fixed cube (gnomonic projection, blended across the seams where another component is within 18 % of the largest: threshold 0.82). An octave fades on log2(FP · f) over −2.7 to −0.7 (full below about 0.15 cycles per pixel, gone at about 0.62), instead of a linear fade over a factor 2.4. Constants `artistic`. Moon to confirm the look. Owner: Atish.
- **Q-352 Smoother reads of the height and climate grids (#93 2.7).** The fly view reads the 720 × 360 height grid (`uHt`) and the climate grids (`uEb`, `uEb2`) with cubic reads for shading, and the haptics and sound read the same filter (`engine/worlds/fieldSampler.ts`); the ray march and the shadow steps keep the bilinear read. **Final filter (#93 regression fix, 12 Nov 2026):** the B-spline approximates, so it flattened narrow peaks (a one-texel peak read a third of its height) and drew some land as sea. The height reads for shading now use a Catmull-Rom cubic (from 9 bilinear taps; it passes through every texel value); the climate grids keep the B-spline. The low-frequency coastline warp of phase 2 is dropped (it moved the drawn heights up to 80 km, at Earth size, away from the climate, rivers, the CPU terrain and the haptics); the warp is the prototype's two fine octaves again. `fieldSampler.ts` reads heights with the same Catmull-Rom (16 texels) and climate with the B-spline, so sound and touch match the picture. Fly frame time (RTX 4060 Ti, phase 1 / phase 2 / now): TRAPPIST-1 f 14.9 / 16.6 / 14.3 ms, Earth 15.0 / 15.9 / 13.8 ms; bench page `scripts/engine-bench/relief.html`. Moon to confirm the look. Owner: Atish.
- **Q-353 Rock variety (#93 2.8; amends Q-334 (2), Q-300).** A card body gets `seed3` (seedVec of the card seed's hash) as its noise offset and the full 32-bit hash (`seedHash`) for the shape and crater RNG, instead of the [0, 97) value; per crater an ellipticity, a rim height and a rim wave; 0 to 2 boulders a cell. All `artistic`. The artifact's bodies (Bennu, Eros, 'Oumuamua) have neither field and draw as before. Moon to confirm the look. Owner: Atish.
- **Q-354 #93 deviations in the copied code (amends Q-335).** The #93 changes are `// @deviation (#93 N)` blocks or `@rename` pairs. The world extractor carries them: the block texts are `DEV93_*` in `frontend/scripts/extract-world-engine.py` and the physics ones in `frontend/scripts/world_engine_deviations.py` (`PRESETS_93_*`, `CORE_L*_93_*`), applied after slicing. The pattern blocks carry the labels of the phase 2 plan (`#93 3`, `3.1`, `3.2`, `3.4`, `3.9` in `DEV93_SEED`, `DEV93_PATTERNS`, `DEV93_RIVER`), not the issue's 2.x numbers; `DEV93_PATTERNS` lists the 2.x items inside. The star engine's deviations 4 to 6 (#93 1.9, 2.3, 3.4) are `@rename` pairs 7 to 22 in `engine/stars/protoStar1.js`; the rock engine's (#93 2.8) are in `engine/rocks/source.ts`. Full list: [R5.9](../rendering/engines.md#r59-prototype-engines-d-37). Owner: Atish.

## Q-367 and Q-368 Regression and operations fixes (issue #93)

Spec: [R5.9](../rendering/engines.md#r59-prototype-engines-d-37) and the event run steps [A10.2](../architecture/frontend-platform.md#a102-running-the-event-build). The other #93 regression fixes are recorded in Q-337 (compile numbers), Q-338 (timeouts, fallback, loader), Q-339 (build steps wait for the engine), Q-344 (drag direction) and Q-352 (height filter); the pack rule in [Q-369](demo-pack.md).

- **Q-367 Engines kill switch (#93 C4; amends Q-287: one more condition on the gate).** `?engines=0` in the page's query string (before any `#`; `useHashSync` owns the hash) turns the D-37 engines off, so the three.js path draws every body at every honesty level; `?engines=1` turns them back on. The choice is kept in `localStorage['sx.engines']`, so a reload without the query keeps it; the default is on, and a missing or throwing storage leaves the query in force for that page (`app/enginesSwitch.ts`, `enginesEnabled()`). `ViewerPanel` gates every engine stage on it (world, star, rock and the close-up pane). It overrides the "+ Artistic" engine gate of Q-287. Test: `enginesSwitch.test.ts`. **Status:** Open (built); Atish to confirm. Owner: Atish.
- **Q-368 Chrome's shader cache and the demo warm-up (#93 blue team, 12 Nov 2026).** Measured on Chrome 157 (RTX 4060 Ti desktop): Chrome's GPU disk cache does not keep programs linked through `KHR_parallel_shader_compile`; synchronous links are kept. `FLY_FS`'s entry is only 74 KB, so the cache size limit is not the cause. With `--enable-features=ANGLEPerContextBlobCache` the KHR-linked programs are kept: the second launch was ready in about 52 ms instead of 22 s. So "a warm cache compiles in milliseconds" (Q-337) holds within one Chrome session, or across launches only with that flag. **Procedure:** the demo Chrome is launched with its own profile and the flag, every engine object is opened once at "+ Artistic" after the final frontend build, and a relaunch must show a Surface view ready in under 1 s; if it does not, Chrome stays open for the whole event. The steps are in [A10.2](../architecture/frontend-platform.md#a102-running-the-event-build). The A15 numbers are not measured yet (R12 #55). **Status:** Proposed (Atish to confirm on the A15). Owner: Atish.
