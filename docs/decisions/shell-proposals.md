> **Part of:** the decision log ([index](README.md)) · **Holds:** open proposals for the shell that Track and Area search need: pane kinds, feature cards, hash keys, Escape order, sky extension points · **Authority:** highest; an entry here wins over [rendering/](../rendering/README.md) and [architecture/](../architecture/README.md) (see the index for precedence)

| Q-150 | **One Escape owner for the shell (A21.10).** As built, Escape has four handlers (`PanelCard` onKeyDown, `BuildPane` onKeyDown and window listener, `SelectedCard` window listener, `Island` window listener) and their order is listener registration order. The island's handler neither skips text fields nor calls `preventDefault`, so with the build pane opened from the rail and a search thinking under it, Escape first sets the tool to `sky` and then closes the pane, sending focus to the marker instead of the rail button; Escape in the search field while thinking leaves the panel tool. Proposal: one window listener in `app/shell/escape.ts` with a stack each surface registers on while open; one press closes exactly one thing and calls `preventDefault`, in this order: (1) a text field keeps Escape (the search field blurs and hides its help, as the mock-up); (2) the split pane, any kind; (3) drawing mode (A18.1); (4) the object panel or a feature card; (5) the object card; (6) thinking (leave the panel tool). A surface with focus inside it still closes itself first. The island's handler is removed. Spec: [A21.10](../architecture/sky-shell-behaviour.md#a2110-keyboard-and-escape); Area search [A18.1](../architecture/moving-objects/area-ui.md#a181-tool-and-drawing), Track [A20.1](../architecture/moving-objects/track-ui.md#a201-where-track-lives); [Open conflicts](../architecture/sky-shell-behaviour.md#open-conflicts) row 1. | Moon | Proposed |
| Q-151 | **Pane kinds: Build and Track share the split pane (A21.8; amends Q-113 item 2; follows Q-146 item 2 and Q-131).** As built the split pane is Build only: `build.open` drives `data-split`, the `build` hash key, the `{ sxBuild: true }` history mark, the rail's 3D viewer `aria-pressed` and focus return, and `setTool(any)` closes it. Proposal: (1) `build` becomes `pane: null \| { kind: 'build', animate, seq, seedOffset, from } \| { kind: 'track', objectId, from }`, `from` = `'rail' \| 'card' \| 'panel' \| 'link' \| { area, card }`; `data-split` follows `pane !== null` and `data-pane` names the kind. (2) One occupant: opening a kind while another is open replaces it in place (no slide; the old kind's close without its focus return). (3) Width per kind through `--sx-split-w`: build 50 % (as built); track to decide (the mock-up uses 62 %). (4) Hash: `build` or `track=<object id>`, never both; opening pushes one entry marked `{ sxPane: '<kind>' }`; replacing a kind replaces that entry; closing goes back over a marked entry, else replaces. (5) A rail tool other than the pane's own closes the pane; Area search opens Track with `openPane`, not `setTool`, so its tool stays `area` and its card is hidden meanwhile. (6) Focus on close by `from`: rail button, the object's marker, the sky canvas, or **Back to the area** (reopens that Area card, focus on its heading). (7) Escape closes the pane first (Q-150). (8) What steps aside is the same for every kind; Track's time slider lives in its pane, and its sky marker follows that slider (Q-142) through a marker feed. (9) Atish decides whether Track also gets a rail tool (`ToolId 'track'`, Q-131 "tool id"); if so its button is pressed while `pane.kind === 'track'`. Spec: [A21.8](../architecture/sky-shell-behaviour.md#a218-split-pane); [A18.8](../architecture/moving-objects/area-ui.md#a188-hand-off-to-track); [A20.1](../architecture/moving-objects/track-ui.md#a201-where-track-lives); Open conflicts rows 2 and 3. Track's width (item 3) and rail tool (item 9) are proposed in Q-161 (50 %, no rail tool). | Moon (shell); Atish (Track) | Proposed |
| Q-152 | **Feature cards in the island slot, with close and minimise (A21.5; amends Q-121 item 2 for one new mode; follows Q-146 item 3).** Q-121 makes the island decorative (no clicks); Q-146 and A18.4 want Area cards that minimise to a pill showing progress. Proposal: (1) a tool's card ("feature card") renders in the object card's slot (`.sx-island-wrap` place, z 25), shown only while `tool` is that tool, so it never meets the object card (`tool === 'sky'`); width 340 px like the object card unless a width token is decided (A18's 408 px is a mock-up value). (2) Header: title, ×, **Minimise** (`aria-expanded`, `aria-controls`); × returns to the previous card or the sky and focuses the tool's rail button. (3) Minimise gives the island a new mode `progress`: a pill at the island's rest place with the card's one-line progress text; only in this mode it takes clicks, as a `button` "Show <card title>" with `aria-expanded="false"`; click, Enter or Space restores the card and focuses its heading; minimising focuses the pill; the text changes in a polite status at most once per step. (4) Precedence: `thinking` > `progress` > `idle`. (5) Right-click on the sky keeps its Q-120 meaning (the object card) and does not restore a feature card. (6) Reduced motion: no animation; phone: the pill shows over the top of the sky like Thinking. Spec: [A21.5](../architecture/sky-shell-surfaces.md#a215-overlay-surfaces-island-object-panel-object-card); [A18.4](../architecture/moving-objects/area-ui.md#a184-cards-and-minimise); Open conflicts row 4. | Moon | Proposed |
| Q-153 | **Hash keys for tools and panes (A21.11; extends Q-95 and Q-113 item 2).** As built `parseHash` reads only `ra, dec, name, frame, colour, build`, `currentHash()` rebuilds the whole hash so any other key is wiped on the next write, and a hash with no object and no `build` shows "This link has no object name or coordinates." Proposal: (1) every key is declared in `HashState` (`app/urlHash.ts`); no feature touches `location.hash` itself. (2) New keys: `track=<object id>` (Track pane, Q-151), `area=<area_id>`, and `atrack=<track_id>` for a Discovery track (A18.9's `track=` would clash). (3) `currentHash()` merges object keys, the pane key (`build` or `track`, never both) and the active tool's keys; every write goes through it. (4) A hash with a pane or tool key and no object is valid. `area=` sets the tool to `area` and opens that area's card; an unknown area is a link problem, never guessed. (5) A new area or opening a pane pushes; choosing a Discovery track or step replaces; Back closes the pane first, then leaves the area. Spec: [A21.11](../architecture/sky-shell-behaviour.md#a2111-url-hash-and-history); [A18.9](../architecture/moving-objects/area-ui.md#a189-state-api-client-accessibility-performance); [A20.1](../architecture/moving-objects/track-ui.md#a201-where-track-lives); Open conflicts row 5. | Moon | Proposed |
| Q-154 | **Sky extension points: pointer mode, layer hit-tests, layer slot, safe rectangle, camera command (A21.2, A21.6, A21.13; follows Q-120 and Q-124).** As built the canvas handlers always pan on drag and pick on click; only `resolved` can move the camera; markers and labels ignore the insets. Proposal: (1) a pointer mode `'pan' \| 'draw'` in the shell store: in `draw` a primary drag and a click go to the registered draw handler, crosshair cursor, wheel and pinch still zoom; Escape or leaving the tool sets `pan`. (2) A layer hit-test chain: on a click, marker buttons first (DOM), then registered layers topmost first, else the pick; on a right-click, the 44 px marker rule first (Q-120 object card), a layer's `contextHit` only when no marker is within 44 px. (3) The sky layer slot: a SkyPane child after `.sx-sky-shade` and before the object card and panel, z auto, `pointer-events: none`, drawn from `view.onRender`. (4) The safe rectangle (`skySafeRect()`): the sky minus `--sx-in-t/l/b/r`, `--sx-credit-h` and the open panel or card; labels clamp to it and markers outside it fade. (5) `skyFlyTo({ ra, dec, fovDeg? } \| { box })`: one camera command in a store, 700 ms ease-out cubic, centred on the safe rectangle, instant under reduced motion, cancelled by pointer-down, wheel or a key move; the `resolved` fly-to becomes one caller. (6) A layer appends its text alternative id to the canvas's `aria-describedby`. Spec: [A21.2](../architecture/sky-shell.md#a212-layout-insets-safe-rectangle-z-order), [A21.6](../architecture/sky-shell-surfaces.md#a216-sky-interaction), [A21.13](../architecture/sky-shell-behaviour.md#a2113-adding-a-tool-or-a-sky-layer); [A18.1](../architecture/moving-objects/area-ui.md#a181-tool-and-drawing), [A18.2](../architecture/moving-objects/area-ui.md#a182-sky-layers-frontendsrcappskyareaarealayertsx), [A20.4](../architecture/moving-objects/track-ui.md#a204-path-on-the-sky); Open conflicts row 6. **Status note (9 Nov 2026):** item 1 also needs a way back to `pan` after drawing, or a click after the square goes to the draw handler and A18.2's track picking never runs; A18.1 and A21.6 now say that releasing a valid square sets `pan` and **Draw again** sets `draw` (part of this proposal). | Moon | Proposed |
| Q-155 | **A tool that owns the sky: what a search does, and the transport (A21.4, A21.9, A21.13; follows Q-120 items 1 and 3, Q-89).** As built every new search from input, a link, a pick or a marker left click switches the tool to `flipbook` (unless flipbook or spectrum, build open, or a right-click card request), and the transport is the flipbook's. A18 wants click-to-pick to keep working inside Area, a right-click to bring an Area card back, and visits in the transport. Proposal: (1) a pick or marker click while a sky-owning tool (`area`) is active leaves that tool for the object panel, as today; the tool keeps its state in its own slice, so its rail button brings back its last card; A18.5's **Open** on a Known row is that left click. (2) Right-click keeps Q-120's meaning (object card). (3) The transport has no modes: a tool with its own time control puts it in its own surface (Area: the Discovery card; Track: its pane); A18.3's "the transport bar shows visit v of V" is replaced. Spec: [A21.4](../architecture/sky-shell.md#a214-tool-rail-and-toolid), [A21.9](../architecture/sky-shell-behaviour.md#a219-transport-session-search-pill), [A21.13](../architecture/sky-shell-behaviour.md#a2113-adding-a-tool-or-a-sky-layer); [A18.3](../architecture/moving-objects/area-ui.md#a183-visits-and-blink), [A18.5](../architecture/moving-objects/area-ui.md#a185-options-and-known-objects); Open conflicts row 7. | Moon | Proposed |

| Q-173 | **Desktop Feel mode (Q-113 item 5, Q-132, Q-133; R5.6, R5.8).** The event has no finger, so "Touch mode: one finger feels" cannot apply. Proposed: the build pane's Feel toggle turns Feel mode on; hovering plays nothing; a primary-button drag on the body plays the body tone for the point under the pointer and does not rotate (orbit off while the button is down; the wheel still zooms); arrows and the on-screen rotate buttons still rotate, and with the canvas focused a held arrow key plays the tone for the surface point at the centre of the body's disc (a fixed probe for keyboard users); leaving the body, releasing, turning Feel off or hiding the page stops the tone.
