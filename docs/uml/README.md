# UML diagrams

Architecture diagrams for **Shift & Spectrum**, written in Mermaid. They illustrate [decisions/](../decisions/README.md), the [architecture spec](../architecture/README.md) (sections A…) and the [rendering & haptics spec](../rendering/README.md) (sections R…) as of 9 Nov 2026 (the event is a desktop browser on the A15 laptop, sound only, Q-132; the shell is A21; Track A19 and A20; Area search A16 to A18).

> **The specs win.** If a diagram differs from a spec, the spec is right and the diagram is out of date. Precedence: `decisions/`, then the rendering doc for its scope, then the architecture spec. Update the matching diagram in the same commit as any spec change.

Mermaid renders natively on GitHub, and in VS Code with a Mermaid extension (for example "Markdown Preview Mermaid Support"). Items marked **[verify]** or pointing to an open Q- question are not settled in the specs.

## Conventions

- Dashed nodes, edges or states are post-event items (B-01 to B-04, and everything Q-132 moves after the event), stretch goals (P3), or parts that are **to build** or **proposed** (no decision yet); each diagram's intro says which. Class diagrams mark them with a stereotype such as `<<stub, B-01 post-event>>` instead, because Mermaid class diagrams cannot dash a single class.
- Diagrams apply `decisions/` where the specs still show older text: ObjectCard and RenderParams replace the settings file (D-02), three r187 (D-03), the union `ObjectType` (D-04), web-only haptics with quantised strength (D-08, D-09), audio paired on every platform (D-10) and the shared field for shader kinds (D-12).
- Each file has been checked with `@mermaid-js/mermaid-cli@11.4.2`; since 9 Nov 2026 every block also parses with mermaid 10.9.1. Do not put a `;` inside a sequence message, note or `alt`/`opt` label: Mermaid reads it as a statement break.
