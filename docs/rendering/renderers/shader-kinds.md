# Renderers: shader-generated kinds

> **Part of:** Rendering & haptics spec ([index](../README.md)) · **Sections:** R7.7 · **Implements:** D-01, D-04, D-12, D-21 ([decisions](../../decisions.md))

### R7.7 Shader-generated kinds: `planet_rocky`, `planet_water`, `gas_giant`, `nebula`, `nova`

- **Look:** browser shader generators with triplanar mapping, as in [architecture spec §6](../../architecture/README.md) (D-01). This doc does not restate them.
- **Shared CPU field (D-01, D-12):** planets and gas giants need a field the finger can sample.
  - When a body loads, a Web Worker generates one equirectangular field at **512×256**. It runs once, not per frame.
  - It uses the **same seed and the same functions** as the shader, so the field and the picture agree.
  - Six channels, packed into two RGBA `Float32` `DataTexture`s (D-12). The haptics read the same `Float32Array`s.
    - Texture A: R = height, G = band index, B = storm id, A = unused.
    - Texture B: R = ocean mask, G = ice mask, B = lava-crack mask, A = unused.
  - Pixel-to-direction mapping as in [§6.1](../surface-generation.md#r61-strategy-height-first-colour-second).
  - The field is uploaded to the shader as a `DataTexture`. The haptic sources ([§8.4](../haptics/sources.md#r84-event-sources)) sample the **same array**. Principle 6 ("one height map drives everything") holds for these kinds too.
  - The shader may add finer visual noise below the field's resolution. That detail is seen but not felt.
- **Nebulae and novae** (issue #43) are emission-only **volumes**, ray-marched in a box with per-pixel `interleavedGradientNoise` jitter (TAAU smooths it) and steps by quality level (`TIERS[..].volumeSteps`: 96, 64, 40). Density comes from a deterministic 48³ noise cube baked on the CPU (`volume/noiseVolume.ts`) in time slices of about 6 ms (`bakeNoiseVolumeSliced`, same bytes as the one-shot `bakeNoiseVolume`, cached by seed), so no long task blocks the page; the volume is empty until the cube arrives, then the viewer redraws from a fresh temporal history (`onVolumeNoiseReady`) and `whenSettled` waits for the bake. The ray start is also shifted per frame by the TAAU frame index (`jitterShiftForFrame`, golden-ratio steps; index 0 after a restart, so a settled frame is deterministic). Volumes are depth-tested against the opaque bodies but never write depth, so the comet nucleus hides the coma and tails behind it while volumes still add up; the test uses the far face of the box, so a pixel the nucleus covers also loses the thin volume in front of it. The nova is the supernova remnant (Q-59): a smooth synchrotron core glow, thin filaments on a shell (H-alpha red, [O III] teal), dust absorption lanes and an outline from the size and axis ratio (no card field holds the axis ratio yet, so a circle). The age slider moves the shell by the Sedov law `(t/t_max)^(2/5)` relative to the slider maximum (`artistic`); phase names wait for transition times that are **[verify]**. No point sets are generated and there are no haptics for either kind (Q-103): what is felt must match what is drawn (D-34), and the old point-density pulse would have been felt where nothing is drawn. The plan adds a plain-words note ("Nebulae have no touch feedback"), so Touch mode on one is not silent without a reason (R9).
- **Gas giant layers (issue #62, Q-115):** a gas giant's surface is five layers, one per rung of the tier chain (D-32), each with its own switch: `bands` (Rhines count, A7.2; `inferred_from_analog`, tier 4: the card has no wind, so the typical 50 m/s is in `assumed`, and that value is unverified, so even a measured spin leaves the layer at tier 4, Q-119, Q-110; with no `rot_period_h` the typical spin is used and is in `assumed` too), `flattening` (`f = f_J (P_J / P)^2`, Jupiter density assumed, `model_dependent` with a measured spin, `inferred_from_analog` with none), `colour` (palette family from `teq_K`, `derived`; `artistic` default without it), `storms` (`artistic`: count and place are seeded) and `turbulence` (`artistic`). In Measured only none is drawn (a plain sphere of the measured radius), "+ Estimated" draws bands, flattening and colour, "+ Artistic" adds the storms and the turbulence, and the viewer's `jets` and `storm_drift` (artistic). Jupiter's period (9.925 h) and flattening (0.06487) are verified (NASA Jupiter Fact Sheet; IAU WGCCRE 2015; Q-119); the typical wind is a **[verify]** config value; all are config values (`gas_giant.py`, `shaderSpec.ts`; a backend test keeps the twins equal); `null` refuses the layer.
  - **What the legend says is what is drawn (PR #63 review, Q-115):** the viewer draws `bands` and `flattening` from the motion rates (`dynamics`, each with its own tag) and, above all, the sliders, which can be weaker than the backend layer (the backend knows only the card). So the legend's `bands` and `flattening` take the **weaker of the backend layer's tag and the viewer rule's tag** (`bandsRule`, `flatteningRule`), and their description, formula and `assumed` come from the rule that sets the drawn value (the band count quoted is the drawn one, pole to pole). A `bands` slider, or a flattening from the `mass_mearth` slider, is `artistic` (a plain-words line says it is the visitor's choice). The honesty switch for the layer uses the same weaker tag. The backend layer's refusals are kept: a layer the backend did not send (an older saved result) is refused with reason `backend` and listed in `missing`, never dropped. The plan reads the sliders from `PlanContext.overrides`.
- **Honesty:** the surfaces of planets, nebulae and novae are not measured, and every texture layer and texture haptic is `artistic` (a gas giant's own layers are the five above). In Measured only, texture haptics are silent. The data pulse (`teq_pulse`) remains only when `teq_K` is `measured` (Exoplanet Archive `pl_eqt`, D-21).
- **Haptics:** terrain and flow sources ([§8.4](../haptics/sources.md#r84-event-sources)), profile rows in [§8.5](../haptics/profiles.md#r85-per-type-haptic-profile).
- **Implementation (issue #8):**
  - `viewer/fields/fieldGenerator.ts` (pure, seeded, integer-hash noise) is the source of truth for the field; `fieldWorker.ts` wraps it and `fieldClient.ts` falls back to the main thread. `FieldSampler` is the typed sampler for haptic sources.
  - The shader reads the two textures with `textureLoad` and filters by hand, so float32 filtering support does not matter. It recomputes only sub-resolution noise and the analytic storm shapes (centres from `stormsFor`, the same function the field uses).
  - Gas giants: R holds the band profile (0.5 is a band edge), G the band index, B the storm id; a gas giant has no relief (Q-48). Terrain: R is the raw terrain height, ocean flattened by consumers using the ocean mask.
  - Determinism is **per engine**: the noise uses only exactly specified operations, but the field also calls `Math.sin`, `cos`, `acos`, `atan2` and `pow`, which ECMAScript only approximates, so two engines can differ by an ulp and flip a lattice cell. The tests run on V8 only.
  - Seeds: `RenderParams.seed` is unbounded (Q-35), so the CPU reduces it with `boundedSeed` (mod 997, in `shaderSeedOffsets`) before it is added to float32 shader noise; the integer-hash field uses the low 32 bits of the seed (`hash3` takes `seed | 0`), so seeds that differ only above bit 31 give the same field (relevant to Q-35).
  - Shared with the shader, not packed: `zonalWind(d, params)` (counter-flowing jets), the ring geometry and `ringGapAt`, and the storm ring constants behind `STORM_EDGE_FACTOR` (1.9, was 1.5; the felt storm area grows about 1.6x, signed off by Atish as haptics owner, D-13), so the felt edge is the drawn edge (Q-48). `zonalWind(d, params)` takes the direction and uses the same warped band phase as the drawn bands.
  - **Starlight and climate scenario (issue #68, Q-155 to Q-157):**
    - Layer `starlight` (`PlanBuilder.draw`, viewer-added; requires `host_teff_K`): the DirectionalLight colour is `planLighting(...).colour`; `ShaderBody.setSunColour` multiplies it into the atmosphere rim and sky glint. Cleared to white when the layer is hidden or refused.
    - Layer `climate` now names the scenario: `shaderSpec.ts::deriveClimate` (via `physics/climate.ts`) runs for a card that carries the host-star fields and a `teq_K`. `eyeball` and `snowball` replace the polar-ice rule and set `FieldParams.substellar` and `iceAngleRad`; `temperate` keeps the rule, weakened to the locking tag; `lava` and `hot_dry` keep the rule as it was. A refused locking rule lists `tidal_locking` in `missing` with the field it lacked.
    - Field (`fieldGenerator.ts`): in substellar mode ice is `smoothstep` over the angle from +X (longitude 0, the middle column) with the seeded `wob` edge, ocean stays where the terrain is below sea level inside the cap, ice covers everything outside it (the night side included), `iceAngleRad` 0 is a snowball (a water world is all ice, bare rock keeps a little high ground bare), and `iceExtent` is ignored. Without `substellar` the bytes are those of the polar rule. The params travel whole through the worker, the client fallback and the main thread, so the three paths give the same bytes.
    - Climate pattern at + Estimated: when the artistic surface is hidden and the scenario is `eyeball` or `snowball`, `plan.shader.pattern` is true (the climate layer is drawn from its own tag) and `ShaderBody` switches its pattern mode on from the visible tags: bump, colour, clouds, atmosphere and lava are replaced by the field's ocean and ice masks in `PATTERN_GROUND`, `PATTERN_WATER`, `PATTERN_ICE` (fixed key colours, not a claim about the surface), on a smooth sphere at the measured radius. The pattern is drawn from the ice mask alone: a uniform open-cap colour (water or ground) inside the cap and ice outside it, so the ocean mask's noise-derived coastline and the snowball's bare high rock (both artistic terrain) are ignored; a snowball is uniform ice. The locked pose and the no-spin rule apply. At Measured only the plain grey sphere stays, in white light. Nothing `artistic` is visible at + Estimated.
    - Not yet here: scenario looks (`viewer/looks/`, Track C).
  - Gas giants are lit by the scene's DirectionalLight like the planets: the one direction comes from `planLighting(params, card).direction` (phase angle, else `sun_dir`, else head-on `[0,0,1]`; none when self-lit), the same value for the scene sun and the body. `planet_rocky` lava cracks glow only when `teq_K` is known and above about 700 K ([A7.1](../../architecture/physics.md)); the ramp to full strength (1500 K) is **[verify]**, artistic.
  - Nebula and nova make no point sets since issue #43 (the picture is a volume with no haptics, Q-103). The worker's `points` kind (`fieldWorker.ts`) stays for a later CPU twin of the noise cube; nothing requests it now.
  - Entry point: the shader kinds use the same path as the baked kinds, `ViewerApp.setObject` to `planRender` to `buildScene`. `renderers/shaderPlan.ts` plans them with `PlanBuilder` (legend, `missing`, notes, scale bar), `buildScene` creates the `ShaderBody` from `plan.shader` (`ShaderBody.start`: the plain sphere is there at once, the surface swaps in when the field is ready, so the view is never blank) and `ViewerApp.body` exposes it to haptics. The body gets `visibleTags` from `allowedTags(plan.honesty)` (the D-21 start state, + Estimated, hides the `artistic` surface), its light from the plan, and `onChange` from `BuildHooks`. A plan whose `sceneKey` is unchanged (honesty, light or mode changed) calls `BuiltScene.update(plan)`, which sets the tags and light on the same body: the field is **not** regenerated on an honesty toggle. A failed field is reported through `onLoadFailed('surface')`, so the plan refuses the layer with reason `load`.
  - Plain sphere (Q-45): when the surface is hidden, planets and gas giants keep a plain grey sphere only while the size on the card (`radius_rjup`) is shown at the honesty level, so at Measured only it stays only when the size is `measured`. Nebula and nova have no plain sphere and draw nothing while hidden. The plan (`plan.shader.plain`) and the body apply the same rule.
  - `BodyRenderer` (plug-in shape): `field` (a `FieldSampler`, null for the nebula and the nova), `pointSets` (null for every kind now), `worldToBody(p)` (undoes the gas-giant tilt and group scale), `status` (drawn / hidden / refused with a plain-words message and tags), `altText` (the panel builds its own from the plan in `altText.ts`), and `ctx.onChange` so a render-on-change viewer redraws after tag changes and rebuilds. A rebuild builds the new surface before dropping the old one (never blank), and frees it if the body is disposed or superseded first. `status.tags` lists what is on screen, so it is empty when only the plain grey sphere or nothing is shown. The R5.3 tag chip and the D-02 badge come from the plan's legend (`plan.drawn`, shown by the panel's "What is drawn" list), not from `status`. A standalone body defaults `visibleTags` to + Estimated (Q-49).
  - Layer `surface` (planets, gas giants) or `point_cloud` (nebula, nova; the id is kept, the layer is now drawn as a volume) is refused, and listed in `missing`, when `scale_m` or the size field is null, or when the backend lists it in `RenderParams.missing`.
- **Motion (issue #42, Q-104):** `ShaderBody.setTime(time)` poses the body from the SimClock. Gas giants: counter-flowing jets (detail advected by the zonal wind, flow-map cross-fade), storms that drift and turn (`fields/flowModel.ts`, handed to the shader and to `FieldSampler.setStorms` at the same t), flattening from the spin, band count from the Rhines rule. Worlds: clouds carried by latitude winds with cloud shadows, single-scattering atmosphere rim, ocean Fresnel and Sun glint, ice and ocean from the A7.1 Teq thresholds. Each sub-layer is listed with its tier; nothing moves without a stated speed-up.
