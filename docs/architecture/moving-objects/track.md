## A19 Track

Track follows **one known solar-system object** across the SPHEREx frames that caught it: its path seen from SPHEREx, the frames, a north-up zoom with stars masked and a spectrum built exposure by exposure. This fragment owns the data; [A20](track-ui.md) owns the screen.

### A19.1 Scope

- Known objects only: ids with `moving = true` (solar-system bodies, Q-22). No blind search and no discovery claims (Q-131); Discovery is Area search ([A16](area-search.md)).
- **MVP demo:** 433 Eros on its 20 to 21 Mar 2026 frames (Q-137). 3I/ATLAS is a stretch goal (A19.8).
- The demo is frozen on QR2 with a local cache on the A15; no switch to DR1 before the event (DR1 was released in November 2026, month only, see [A3.1](../data-sources.md#a31-spherex-irsa); Q-137).
- Desktop browser only (Q-132). Sound is specified in R8.9.2 ([audio-pairing.md](../../rendering/haptics/audio-pairing.md)).

### A19.2 Entry points

Track receives one thing: the object id that `/v1/resolve` returns (D-16). It never takes positions from the caller.

| From | Id comes from | Spec |
|---|---|---|
| Area search, Known card, **Track it** | `/known[].object_id` (A17.5) | [A18.5](area-ui.md#a185-options-and-known-objects) |
| Area search, Discovery, **Open in Track** (found blind only) | `match.object_id` (A17.5) | [A18.7](area-ui.md#a187-result-card) |
| Object panel of any `moving = true` object, **Track it** | the resolved id | **Proposed (Q-181)** |
| A link with `track=<id>` in the hash | the hash (A21.11) | [A20.1](track-ui.md#a201-where-track-lives) |

Track is the `track` kind of the shell's split pane (A21.8 in [sky-shell-behaviour.md](../sky-shell-behaviour.md), pane kinds proposed as Q-171), not a rail tool: it has no `ToolId` (**Proposed (Q-181)**, amending Q-131's "tool id"). An id with `moving = false` is refused in the frontend as `track:not_moving`.

### A19.3 Frame list

- **Source:** `GET /v1/objects/{id}/frames`, the moving-object path search of [A4.1](../pipeline.md#a41-stage-1-find-the-object) as PR #53 built it: one SPHEREx-centred Horizons ephemeris per window, SIA cones along the path, merged by `frame_id`, kept when the exact `TLIST` position at the frame midpoint is inside the frame's `s_region`. Its settings (`SX_MOVING_*`: cone radius, step clamp, cone cap, MAXREC, pacing) are **[verify]** (`backend/app/settings.py`; A3.1 "Moving objects" row).
- **Track window:** the target's `moving_windows` in `backend/targets.toml`. For 433 Eros: `[["2026-03-20T00:00:00Z", "2026-03-21T12:00:00Z"]]` (**Proposed (Q-184)**). Without it the default window covers the whole release (a live search for 20 Mar to 10 Apr alone found 102 frames). Result: 16 frames (2 visits × 4 exposures × 2 detectors) with production settings, checked 11 Nov 2026 (issue #73) with `uv run python -m scripts.prefetch --only "433 Eros"` (`frames=16 cutout_failures=0` on the second run; the first fetched 14 with 2 cutout failures) and offline with `SX_OFFLINE=1` (`/frames` returns 16).
- **Track on demand (as built, issue #142, [Q-468](../../decisions/moving-objects.md), proposed):** `POST /v1/objects/{id}/track` with `{"around": <ISO time>, "days": 3}` (default 3, 1 to 15, "wider on request") limits the path search to `around` +- `days`, so an object found in an area is tracked without the bulk pre-fetch (Q-461), which takes hours on a busy area. The frontend passes the area visit's time. The window is a parameter of each call, never stored: `MovingConfig.from_context(ctx, spkid, track)` clips it to the window above (the target's `moving_windows`, else the release window), and the clipped windows are in the frames key, so the window has its own entries. The Track readers (`/frames`, `/path`, `/spectrum`, `/overlays`, the PNGs, `/job`, `/job/events`) take the same `around` and `days`; every other caller (the card, the pre-fetch, the areas' `track_available`) keeps the base windows. The route starts that window's Track job ([A4.10](../jobs.md#a410-object-job-and-fan-out)): the Horizons path, the cones (only inside the window, tested), the cutouts and Stage 2, with no card; it replies 202 with the `/job` JSON. On the recorded Eros fixture the job ends with `track_available` true. Refusals and the full contract: Q-468 and [A4.11](../endpoints.md).
- **Footprint for movers:** the overlays reply serves each frame's `s_region` as `footprint` for movers too (the path search already reads it), instead of refusing `footprint:<id>`. **Built** (issue #74): the frame record keeps its `s_region` (`FrameRecord.s_region`), and a mover's frames key gains `m_record` so a list stored before it is rebuilt from the cache ([A4.9](../overlays.md#a49-overlays-flag-mask-and-combine)).
- **MOST:** whether IRSA's Moving Object Search Tool replaces the cone search is one question: [Q-126](../../decisions/moving-frames.md) (PR #53's entry, Kevin) and [Q-140](../../decisions/moving-frames.md) (this branch's) ask the same thing. Q-140's data point (about 115 images over 10 to 31 Mar 2026 against 16 in the 2-day fixture) compares different windows and has to be redone over one window. Open: whether MOST positions are SPHEREx-centred **[verify]**.

### A19.4 Positions

- **Observer:** SPHEREx, `500@-163182` ([A3.4](../data-sources.md#a34-jpl-horizons), Q-138). Everything Track draws for the object uses it: path, marker, predicted ring, path segment in the zoom.
- **At each frame:** an exact Horizons `TLIST` at the frame midpoint (`exact_positions` in `backend/app/core/find/moving.py`). The 3σ RA/Dec uncertainty is added from the same request (Horizons quantity 36 **[verify]**); the code does not ask for it yet (`QUANTITIES='1'`), so `/path` serves `ra_3sigma_arcsec` and `dec_3sigma_arcsec` as `null` (cut for the event, issue #74).
- **Path line:** the 10-min samples of the same ephemeris (`SX_MOVING_EPHEM_STEP_MIN`, inside the ~95 min orbit, so the parallax wobble is sampled). Windows are never joined across a gap.
- **Marker between exposures** (Q-142): linear in the unit vector between the two nearest 10-min samples (the path search's interpolation formula, A4.1 step 3). Error bound for a parallax amplitude `A` and orbital period `P`: about `A·(π·h/P)²/2` for a step `h`; for Eros (`A` ≈ 25″, `h` = 10 min) about 1.4″ (0.2 px) **[verify]** against the TLIST positions. At an exposure time the marker snaps to the exact TLIST position. An hourly table is never used (up to 6″ on Eros, Q-138). **Proposed (Q-185)**, clarifying Q-138 and Q-142.
- **Tags:** RA/Dec, `x`/`y`, path and marker `model_dependent`, with the path search's assumption ([Q-125](../../decisions/moving-frames.md)): "JPL Horizons orbit solution; astrometric RA/Dec (ICRF) seen from the SPHEREx spacecraft (CENTER=500@-163182), TIME_TYPE=UT, at the frame midpoint" (for the path: "every 10 min, linear between samples").
- **End of the SPHEREx ephemeris:** Horizons' SPHEREx ephemeris ends 2026-12-07 (Q-62). The cached QR2 frame times end on 2026-05-14 (A3.1), well before it. A time without a SPHEREx ephemeris is refused (`path:observer`); Track never falls back to the geocentre (the lighting fallback of Q-62 is a different use). The resolve-epoch position (14 Nov 2026) is never drawn in Track (Q-142).

### A19.5 Path endpoint

`GET /v1/objects/{id}/path[?start=<iso>&end=<iso>]` (Q-141, open, Kevin). Beyond D-16; a D-16 note is pending. Listed in the endpoint register [A4.11](../endpoints.md).

- **Reply:** `{id, observer: "500@-163182", step_min, windows[{start, end}], points[{time, ra, dec}], frame_points[{frame_id, time, ra, dec, ra_3sigma_arcsec, dec_3sigma_arcsec}], tag: "model_dependent", assumption, formula, interp_error_arcsec, missing, fetched_at, cached_at}`. Times ISO-8601 UTC with `Z`; RA in [0, 360).
- **Cache only.** As built (issue #74, Q-141 option b): no `derived.path` entry. Each request reads the Horizons range answers the path search already fetched and cached (`horizons.range_key` of `moving.range_chunks`, the same keys), so the object job (Q-111) fills them in the same run as the frame list. When one is absent and the backend is online, the request starts or joins the job and answers 200 with `points: []` and `missing: ["path:deferred"]`; the frontend polls as for frames (Q-97: one request in flight, backing off). Offline and absent: `path:not_cached`. `interp_error_arcsec` is measured, not assumed: the largest separation between the interpolated samples and the exact TLIST position over the reply's frame points (6.2″ on the fixtures' 60 min step; `core/find/path.py`).
- **Size cap:** `start`/`end` are clipped to the windows; a span over 31 days **[verify]** answers 400 `path_span_too_long`. Without parameters: every window when the total is under the cap, else the first window; as built, a first window longer than the cap is served for its first `SX_PATH_MAX_SPAN_DAYS` (ASSUMPTION, issue #74), and `windows` names the span served. An explicit `start` after `end` is 400 `bad_request`; with only one of them, the open side reaches at most the cap from the given side, never a 400.
- **Codes in `missing`** (A19.10): `path:deferred` (the job is filling the entry; poll); `path:not_cached` (offline and absent); `path:observer` (a time with no SPHEREx ephemeris, A19.4); `path:ephemeris` (Horizons gave no usable ephemeris for a window: a failed call or a 200 text without an ephemeris block; the reply is incomplete and not stored); `path:window` (`start` and `end` lie outside every window, so `points` is empty); as built also `path:frames_incomplete` (the frame list is not final yet, so `frame_points` covers only the frames listed so far; poll). A `path:deferred` reply serves nothing (`points` and `windows` empty) and keeps the other codes found. Each answer is read with its body checked, so a torn entry counts as not cached and a request never reaches Horizons.
- **Errors:** 404 `not_found` (unknown id), 404 `not_moving`.
- **JPL terms (Q-141):** one Horizons request at a time, with a User-Agent that names the app. A process-wide gate (a lock plus `SX_HORIZONS_PACE_S` **[verify]**) wraps every call in `backend/app/adapters/horizons.py`: resolve, lighting (Q-62), the path search, TLISTs and Area search's checks. An answer that comes back as HTTP 200 text without an ephemeris block (over the limit, or an error) is a failure and is never cached as success. **Not built yet (cut for the event, issue #74):** the path search paces SIA cones (`Pacer` in `backend/app/core/find/moving.py`) but not Horizons, and Q-111 starts the lighting geometry and the frame list together.

### A19.6 Star list for movers

Built once and shared with Discovery's star step ([A17.3](area-backend.md#a173-glitches-stars-and-fixed-dots-cleanpy)), Q-143. **Built** (issue #95, Atish, Q-404): the library is `backend/app/core/find/stars.py`, the cone helpers shared with fixed-target overlays are in `core/find/catalogs.py`, and `core/find/overlays.py` serves it in `/overlays`. The choices for the spec's gaps are **Proposed ([Q-403](../../decisions/moving-objects-review.md))**.

- **Visits:** A17.1's rule on the mover's frames (midpoints from `t_min`/`t_max`, a gap of `visit_gap_h` = 1 h or more starts a visit, both detectors of an exposure stay together). A Track-local copy (`stars.track_visits`) until P3's `group_visits` lands, then imported (Q-403 (8)).
- **Cones:** per visit, one Gaia DR3 cone and one CatWISE2020 cone, built by one function (`stars.mover_visits`) for `/overlays` and the pre-fetch, so both use the same cache keys. Track: at the visit's mean predicted position (the normalised mean of the unit vectors of the frames' TLIST positions, A19.4), radius = the cutout's half-diagonal (254.56″ for the 360″ cutout) + the largest separation between two predicted positions of the visit (Q-403 (1)) + 30″, rounded up to a whole arcsecond (Eros: 301″ for both visits). Area: at the area centre, radius = half the area diagonal + 30″, rounded up; every visit of an area shares that cone.
- **Limits:** Gaia `G < 20` (the fixed-target key, unchanged); CatWISE `W1 < 16.5` **[verify]**, for movers only (a separate cache key; fixed targets keep no W1 cut, Q-51). Track cones keep the 5000-row cap (`overlay:<cat>:truncated`). The area cone uses `STAR_LIST_MAX_ROWS` = 50000 (measured 11 Nov 2026: the Eros area cone holds 32,256 Gaia and 32,333 CatWISE rows); a capped area answer counts as a failed cone (Q-403 (5)). Sources propagated with their proper motion to each frame time (`derived`).
- **One list per visit:** a CatWISE source within 3″ of a Gaia source, compared at the CatWISE epoch MJD 57170 (Gaia propagated back, CatWISE as given), is the same star: one entry with the Gaia id and position and the CatWISE id kept. Pairs are matched one to one, closest first (Q-403 (3)).
- **Mask radius from magnitude** (starting values, **[verify]** on the Eros frames): Gaia `r = clamp(2 + (14 − G), 2, 10)` px; CatWISE `r = clamp(2 + (11 − W1), 2, 10)` px; a source in both catalogues takes the larger of the two (Q-403 (4)); rounded to 0.01 px. A fixed `G < 20` cut with one radius over-masks in the Galactic plane (Q-143).
- **Shown near the track only:** `frames[].masks` lists the stars inside the cutout whose centre is within 8 px **[verify]** of the polyline through the visit's predicted positions placed with that frame's WCS (Q-403 (2)). `{catalog, id, x, y, r_px}`, tag `derived`; `[]` for fixed objects. The markers and the Gaia/WISE toggles are unchanged.
- **Contamination:** the aperture and annulus lists of [A4.9](../overlays.md#a49-overlays-flag-mask-and-combine), computed at the predicted pixel. A4.9's rule that the nearest source within 2 px is the target itself (Q-53) does not apply to movers: a mover is never a catalogue source.
- **Refusals in `/overlays`:** a catalogue is available only when every visit's cone is served; each frame uses only its own visit's cones (Q-403 (7)). The cones are built only from a complete frame list: while frames are still deferred to the object's job (`cutouts:deferred:`, `frames:search_deferred:`) the reply says `overlay:<cat>:pending`, otherwise `overlay:<cat>`; such a reply is not memoised. One request starts at most 8 new live visit cones per catalogue; the others are `overlay:<cat>:pending` and a later request starts them (Q-403 (6)).
- **Codes:** `overlay:<cat>`, `overlay:<cat>:pending`, `overlay:<cat>:truncated` (A4.9); Area search lists `stars:<cat>:<visit>` (A17.8) from `StarList.missing_codes()`. The library call `stars.star_list(ctx, cone)` never raises: a failed cone, an offline cache miss or an unreadable cached answer puts that catalogue in `failed`.

### A19.7 Photometry for movers

- Stage 2 measures each kept frame at the predicted pixel, with no re-centring ([A4.2](../pipeline.md#a42-stage-2-measure-brightness-and-spectrum)).
- **OUTLIER on the core** (Q-139; the rule's owner is A4.2, ticket T4, Moon): for `moving = true` only, `OUTLIER` within the 1.5 px core is recorded, not refused: the point is `flagged: true` and `flag_reasons` gains `outlier_core`. Hardware flags in the core still refuse (`aperture_flags:<frame_id>`). `MEASURE_VERSION` is bumped (`measure-2`). On Eros: 14 of 16 points (13 with `outlier_core`); the 2 refused frames carry `NONFUNC`, `SUR_ERROR`, `TRANSIENT`. Built in issue #72 ([Q-460](../../decisions/moving-objects.md)).
- **Tags:** the spectrum and light curve stay `measured`; the aperture centre is `model_dependent` ([Q-125](../../decisions/moving-frames.md)).
- Each spectrum and light-curve point carries `frame_id`, so the zoom and the spectrum can follow the same exposure ([A19.13](track-contract.md#a1913-contract)).

### A19.8 Extended sources

3I/ATLAS only, a stretch goal (Q-137, Q-144). Specified here, built after Eros works.

- **Caption** on every point: "aperture, not total flux; background taken from inside the coma" (D-31 precedent). The coma (about 3′) is larger than the 6 to 9 px annulus (37″ to 55″), so the background is coma light.
- **Measurable refusal test** (**Proposed (Q-186)**, making "the coma fills the aperture" measurable): concentration `C = F(r ≤ 1.5 px) / F(r ≤ 3 px)` with the Stage 2 weights. `C_psf` is the median `C` of isolated, unmasked catalogue stars in the same frame (A19.6). A steady coma with brightness falling as 1/ρ gives `C` = 0.5 before the PSF. A frame with `C ≤ 0.5 + δ` (`δ` = 0.05 **[verify]**) shows no point-like core above the coma, so the coma fills the aperture: it is refused as `extended_source:<frame_id>`, and as `spectrum:extended_source` when every frame is. A frame with `0.5 + δ < C < C_psf − δ` is shown with the caption.
